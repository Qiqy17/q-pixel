# Q像素 2.0 专业工作流与写实 3D 成品预览设计

日期：2026-09-22  
状态：用户已确认，等待实施规划与开发  
目标平台：macOS App、桌面浏览器、iPad/平板离线版

## 1. 决策摘要

本轮改版选择“专业创作效率优先”，以稳定的专业编辑器布局为骨架，吸收阶段工作空间的流程组织能力。

已确认的核心决策：

1. 主编辑器采用 `Studio Dock + Workflow Rooms` 混合结构。
2. 左侧工具、中央画布、右侧上下文属性、底部色板的位置固定，保证肌肉记忆。
3. 顶部按“设计、配色、拼制、输出、版本”切换工作阶段，仅替换上下文内容，不移动核心控件。
4. 新增“已有图纸重建”，与普通“照片转图纸”彻底分开。
5. 导入优化永远可跳过，任何智能处理不得直接覆盖当前项目。
6. P0 建立库存约束、多品牌能力、底板输出、跨端拼制与可靠恢复闭环。
7. 原有平面材质遮罩降级为兼容功能；首版直接建设完整写实 3D 成品工作台。
8. 首批真实标定范围为 MARD 5 mm，覆盖十种熨烫/材质效果；其他品牌使用明确标注的未标定通用模型。
9. 写实 3D 必须使用真实样片标定的几何和 PBR 材质，不能以程序滤镜、固定高光或卡通模型冒充。

## 2. 背景与问题

Q像素已经具备图像导入、像素编辑、图层、配色优化、按色拼制、材料统计、区域输出、PNG/PDF/CSV 导出和样式预览等大量能力，但目前主要问题不是功能不足，而是：

- 功能入口散落在顶部按钮、两组浮动工具栏、右侧长卡片列表和多个大型弹窗中。
- 编辑、优化、拼制和输出混在同一界面，信息密度高但缺少阶段感。
- 桌面布局在平板上主要依靠缩小或折叠，触控命中、画布面积和弹窗完整性不稳定。
- “图片转图纸”和“已有图纸识别”缺少清晰区分。
- 原有“样式预览”拥有大量背景、遮罩、边框和灯光选项，但豆体仍是平面色块，材质主要是叠加纹理，不能可信表现实际熨烫结果。
- 主逻辑集中在大型 `web/app.js` 中，功能继续增加会放大重复状态、重复监听和回归风险。

## 3. 竞品结论

### 3.1 我嘞个豆

公开信息显示其优势包括：图纸智能识别、多豆板、范围拆格、库存扫码或手动管理、库存历史撤回、按图纸扣减库存、辅助拼豆、文件夹和多端同步。

可学习：

- 把外部图纸恢复为可编辑工程，而不是再次照片像素化。
- 制作进度与库存联动。
- 大量图纸的文件夹管理和跨端接力。

必须避免：

- 用户评论反映更新后无法启动、导入失败和数据焦虑；Q像素必须坚持本地优先、自动备份和可恢复。

来源：<https://apps.apple.com/cn/app/id6757995987>

### 3.2 颂拼豆

公开信息显示其优势包括：照片转图纸、16–256 画布、色号统计、颜色合并/删除/替换、原图对比、图纸分区、阿尔法锁定、自定义贴图、立体图纸、智能板和创作者生态。

Q像素已实现或已部分实现原图对比、图层、阿尔法锁定、相近色合并、按色拼制、区域输出等能力。

适合后续学习：

- 立体装配图纸。
- 智能豆板连接。
- 贴图和复用资产库。

不进入 P0：

- 社区、装扮和完整创作者生态。

原因是用户评论同时暴露了新版触控难点、角落按钮难点击、闪退、乱码和导出失败；Q像素不以功能数量交换稳定性。

来源：<https://apps.apple.com/cn/app/id6746666092>

### 3.3 其他产品

“我的豆豆”验证了以下高价值能力：像素格识别、智能尺寸、主体重心和对称、自动去杂点补漏格、参考图描绘、多品牌色卡。

来源：<https://apps.apple.com/cn/app/id6761826491>

Beads Studio 验证了以下专业生产能力：真实品牌色号、按库存限制配色、缺豆统计、真实底板规格和一块底板一页的打印方式。

来源：<https://beads-studio.com/zh>

“拼豆先生”具有旋转缩放的 3D 预览，但公开说明未体现多烫法真实材质标定。

来源：<https://apps.apple.com/cn/app/id6762286425>

Hama Universe 提供作品被熨烫的动画；PixelBeads 展示保孔、平融、背熔和多种纹理烫法。当前未发现成熟产品能够针对用户的实际图纸，系统切换多种经过实物标定的烫法并进行可信比较。

来源：

- <https://www.pixel-beads.com/zh>

## 4. 目标与非目标

### 4.1 P0 目标

- 建立专业、稳定、可预测的桌面编辑体验。
- 在平板上提供重新编排的触控工作区，而非缩小桌面版。
- 建立照片转换、已有图纸重建、参考描绘、空白创作四种明确入口。
- 完成设计、配色、拼制、输出、版本五阶段闭环。
- 支持库存约束配色和底板级制作/输出。
- 首版提供 MARD 5 mm 十类实物标定的写实 3D 成品预览。
- 保证本地保存、自动恢复、导入前检查点和同步冲突副本。
- 在 500×500 极限图纸下保持可操作，并能导出 4K 写实预览。

### 4.2 P0 非目标

- 不建设公开社区和完整内容审核体系。
- 不建设装扮、伙伴、积分或游戏化系统。
- 不接入智能豆板硬件。
- 不建设立体装配编辑器。
- 不承诺未经过实物样片标定的品牌具有准确材质。
- 不用虚构温度、时间和压力的精确结果代替真实实验。

## 5. 信息架构

### 5.1 项目中心

项目中心承担：

- 最近项目。
- 文件夹和系列作品。
- 自动恢复记录。
- 本机/平板同步状态。
- 项目版本和冲突副本。
- 跨项目材料汇总（P1）。

新建项目提供四个同级入口：

1. 照片转图纸。
2. 已有图纸重建。
3. 参考图描绘。
4. 空白项目。

入口必须说明结果差异，不能都命名为“导入图片”。

### 5.2 主编辑器

桌面结构：

- 顶部全局栏：项目名、保存状态、撤销/重做、导入、比较、预览、导出。
- 顶部阶段栏：设计、配色、拼制、输出、版本。
- 左侧固定工具栏：绘制、拾色、选区、形状、贴图、辅助工具。
- 中央画布：始终占据最大面积。
- 右侧上下文栏：当前工具属性、当前阶段检查和可执行修复。
- 底部色板：当前色、最近色、使用色、用量和库存缺口。

界面结构在阶段切换时保持稳定。阶段切换只更新：

- 右侧属性内容。
- 中央画布的辅助覆盖层。
- 底部状态信息。

### 5.3 平板结构

- 顶部保留项目和阶段切换。
- 高频工具贴近左侧或手持侧。
- 色板、属性和阶段检查变为可上拉底部抽屉。
- 默认画布优先，抽屉不得永久挤压画布。
- 所有触控目标不小于 44×44 CSS px。
- 768–1179 px 使用覆盖抽屉；1180 px 以上允许完整三栏。
- 键盘快捷键是加速方式，不替代可见入口。

## 6. 五个工作空间

### 6.1 设计

- 画笔、橡皮、填充、拾色、选区、形状、贴图。
- 图层、分组、锁定、阿尔法锁定。
- 原图对比和参考图描绘。
- 对称轴、主体重心、轮廓连续性。
- 孤点、断线、漏格、圆形平滑检查。
- 重要修复先显示前后差异，再确认应用。

### 6.2 配色

- 品牌色卡与自定义色盘。
- 相近色合并、全图替换、删除冗余色。
- 仅使用库存颜色生成或重新配色。
- 缺色替代显示色差、受影响格数和前后比较。
- 锁定关键颜色，防止优化改变肤色、轮廓或指定色。
- P0 以现有 MARD 221 为完整支持对象，数据结构允许扩展品牌。

### 6.3 拼制

- 真实底板规格和多底板分割。
- 按色、按行、按区域三种导航方式。
- 已拼、当前、未拼状态清晰区分。
- 防误触和屏幕常亮。
- 电脑设计后可在平板继续拼制；优先同步进度，不阻塞本地操作。
- 库存扣减必须可预览、确认和撤回。

### 6.4 输出

- PNG、透明 PNG、PDF、CSV 和工程包统一预览。
- PDF 支持一块底板一页、行列坐标、每五格粗线和该页材料数量。
- 输出材料清单、库存缺口和替代方案。
- 普通图纸输出与写实 3D 成品预览分开，互不隐藏。

### 6.5 版本

- 自动保存。
- 命名快照。
- 导入前、优化前和批量替换前自动检查点。
- 崩溃恢复。
- 缺失资源提示。
- 同步冲突生成副本，不静默覆盖。

## 7. 导入设计

### 7.1 通用入口原则

- 选中文件后先显示来源和检测结果。
- 提供“快速导入，直接编辑”和“进入高级优化”。
- 高级优化不是必选步骤，可随时跳过。
- 所有长任务显示真实进度、当前步骤、取消按钮和预计工作量提示。
- 取消不得改变当前项目。
- 应用前创建恢复点；确认后才替换或添加图层。

### 7.2 照片转图纸

沿用并重组现有自适应导入能力：

- 自动判断照片、插画和像素画。
- 推荐画布尺寸和颜色数量。
- 可选抠图、去背景、降噪和结构优化。
- 提供高保真、均衡、易制作候选方案。
- 大图处理继续使用后台 Worker，界面保持响应。

### 7.3 已有图纸重建

该功能目标是恢复原有图纸数据，不是重新创作近似图。

处理流程：

1. 来源分类：截图、扫描件、拍照图纸、PDF 单页或普通照片。
2. 校正：裁边、旋转、透视、黑边和无关装饰清理。
3. 网格检测：格距、行列、起点、多底板边界。
4. 颜色恢复：色块采样、压缩噪声清理、同色归一。
5. 图例识别：OCR 色号、品牌、符号和数量。
6. 置信度审核：集中呈现低置信度格子和色号。
7. 生成副本：保留原图、校准参数、识别报告和撤销点。

置信度行为：

- 高置信度自动通过。
- 中置信度显示原图叠加比较。
- 低置信度进入集中审核列表。
- 任何阶段允许跳过自动步骤并手动校准。

首版范围：

- 图片/截图的裁切、透视和网格恢复。
- 格子颜色恢复和置信度审核。
- 手动校准兜底。

P1：

- OCR 图例。
- 批量 PDF。
- 多品牌图例转换。

## 8. 写实 3D 成品工作台

### 8.1 产品定位

写实 3D 用于制作决策和展示预览，不是装饰动画。

它必须回答：

- 当前图纸用不同烫法后，孔洞、熔接、厚度和表面会怎样变化？
- 正面、背面和双面分别是什么效果？
- 哪些区域连接不足或可能过度融合？
- 当前效果是否来自真实标定？

### 8.2 首批标定范围

品牌与规格：MARD 5 mm。

十类效果：

1. 未熨颗粒。
2. 轻烫保孔。
3. 标准融合。
4. 完全平融。
5. 背熔混合。
6. 毛巾烫。
7. 澡巾烫。
8. 华夫格烫。
9. 闪片烫。
10. 镭射烫。

其他品牌：

- 使用通用几何和材质估算。
- 界面始终显示“未标定通用模型”。
- 不得继承 MARD 的“已实物标定”标识。

### 8.3 交互

- 从“成品 3D”工作空间进入，不再埋在大型样式弹窗中。
- 左侧为十种标定预设。
- 中央为自由旋转、缩放、正视、侧视、背面和 1:1 尺寸视图。
- 右侧显示熨烫面、融合程度、孔径、厚度、材质通道、摄影环境和质量检查。
- 双击或点击单颗豆可检查色号、孔径、连接边和所在底板。
- 支持保存视角、分屏比较和对比快照。
- 支持透明背景 4K PNG 和包含标定说明的预览输出。

### 8.4 写实要求

豆体几何必须真实表达：

- 外径。
- 内孔。
- 高度。
- 顶部倒角。
- 熔融扩张。
- 相邻豆连接桥。
- 正反面不对称结果。

每个标定材质至少包含：

- 基础颜色/反照率。
- 法线。
- 粗糙度。
- 高度或位移信息。
- 遮罩。
- 必要时的透射、闪片或角度变色参数。

光照与颜色：

- 使用经过许可并随 App 打包的 HDR 环境光。
- 使用物理材质、接触阴影和颜色管理。
- 闪片和镭射必须随视角与光线变化。
- 固定亮点、固定渐变和彩色覆盖层不得冒充真实反光。

### 8.5 真实材质生产链

只有完成以下链路的资源可标记“已实物标定”：

1. 使用同批 MARD 5 mm 制作十种标准样片。
2. 在标准色卡、尺寸尺、固定相机、偏振光和多角度灯光条件下拍摄。
3. 生成颜色、法线、粗糙度、高度和遮罩资源。
4. 测量孔径、厚度、扩张和熔接边缘。
5. 使用相同相机和灯位进行渲染/实拍对照。
6. 记录品牌、规格、批次、拍摄条件、制作参数和标定版本。

通用 CC0 纹理可用于背景，不得冒充豆体或烫法表面。缺少真实样片时，可以开发通用模型，但不得宣称已经标定。

## 9. 3D 渲染架构

### 9.1 技术基线

- 使用本地打包的 Three.js ES Modules。
- 使用 WebGL 2 作为首版共同基线，不要求 WebGPU。
- 不使用 CDN；模型、纹理、环境光、KTX2 转码器和 WASM 都必须进入 App 包。
- 3D 模块延迟加载，普通编辑器启动不加载 3D 资源。
- 将 3D 功能拆为独立模块，不继续堆入 `web/app.js`。

建议模块边界：

- `web/3d/finish-viewer.js`：场景、相机、交互和生命周期。
- `web/3d/bead-geometry.js`：豆体、孔洞、熔融形变和 LOD。
- `web/3d/connection-geometry.js`：相邻连接桥。
- `web/3d/finish-materials.js`：PBR 材质和标定资源。
- `web/3d/finish-profiles.js`：十类预设和版本信息。
- `web/3d/performance-controller.js`：能力检测、动态质量和显存预算。
- `web/3d/finish-export.js`：4K 分块渲染和合成。
- `web/3d/finish-validation.js`：资源完整性和标定状态。

### 9.2 批处理与实例化

- 同一几何和材质族使用 `InstancedMesh`，通过实例矩阵和实例颜色表达位置与色号。
- 根据不透明、半透明、闪片等材质族拆分有限批次。
- 相邻连接桥按水平/垂直方向实例化，不为每颗豆建立独立场景对象。
- 预计算邻接关系和实例数据可在 Worker 中完成；WebGL 场景生命周期保持在主线程，降低兼容风险。

### 9.3 分级细节

- 近景：完整孔洞、倒角、连接桥、法线和高分辨率 PBR。
- 中景：降低圆柱分段和阴影采样，保留孔洞轮廓与主要连接关系。
- 远景：低面数实例与压缩材质，保持真实颜色和轮廓。
- 镜头停止后允许逐级补回高质量。
- 大图按镜头覆盖区域和屏幕像素贡献分配质量，而不是仅按总豆数粗暴关闭效果。

### 9.4 纹理与显存

- 标定材质优先使用 KTX2/Basis 通用 GPU 压缩。
- 使用 mipmap 和有限的材质图集，避免每个色号单独纹理。
- 根据视口物理像素和设备能力建立显存预算。
- 离开 3D 工作空间时主动释放不再使用的几何、纹理、渲染目标和 WebGL 资源。

技术依据：

- Three.js `WebGLRenderer` 使用 WebGL 2：<https://threejs.org/docs/pages/WebGLRenderer.html>
- `InstancedMesh` 用于大量相同几何/材质对象并减少 draw calls：<https://threejs.org/docs/pages/InstancedMesh.html>
- `LOD` 支持按距离切换高、中、低细节模型：<https://threejs.org/docs/pages/LOD.html>
- `KTX2Loader` 支持将 Basis Universal 纹理转码为设备可用的 GPU 压缩格式：<https://threejs.org/docs/pages/KTX2Loader.html>
- WebGL 跨设备性能和显存预算建议：<https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices>

## 10. 性能策略

### 10.1 实时预览

- 小图：完整几何、连接桥、接触阴影和最高材质质量。
- 中图：近景最高质量，远景自动降低几何和阴影质量。
- 最大 500×500：只对屏幕可见且有视觉贡献的区域使用高质量几何，远景采用低细节实例。
- 动态降低内部渲染分辨率时，CSS 显示尺寸保持不变。
- 桌面目标为不低于 30 FPS；平板以稳定交互为优先，停止操作后补回质量。

### 10.2 4K 导出

- 导出使用与屏幕相同的相机、材质、灯光和颜色配置。
- 使用分块高质量渲染与带重叠边缘的合成，规避最大纹理尺寸和显存限制。
- 导出过程显示进度、当前块、取消和失败原因。
- 取消导出不改变项目或 3D 预设。
- 透明背景和摄影背景使用同一输出管线。

## 11. 异常与降级

- 缺少标定资源：移除“已标定”标识，指出缺失资源，不静默套用通用纹理。
- 非 MARD 品牌：显示“通用模型·未标定”。
- 显存紧张：依次降低阴影、环境反射分辨率、视口渲染比例和远景细节；近景豆体几何最后降低。
- WebGL 上下文丢失：显示恢复状态并自动重建当前视角、预设和参数。
- 恢复失败：保留项目，退出 3D 工作空间并提供错误报告；不得导致图纸编辑或自动保存失败。
- 不支持 WebGL 2：提供明确标识的兼容预览，不宣称为写实 3D。
- 4K 导出内存不足：自动缩小分块而非直接降低最终分辨率；多次失败后才建议用户降低输出尺寸。
- 所有 3D 资源加载失败均需提供重试和诊断信息。

## 12. 数据与保存

项目保存以下 3D 设置，但不在项目文件中重复嵌入公共大纹理：

- `finishProfileId`。
- `finishProfileVersion`。
- 品牌和规格。
- 标定状态。
- 正面/背面/双面。
- 融合程度、孔径和厚度覆盖值。
- 相机位置、目标点和视角。
- 环境、背景和曝光。
- 保存的比较快照配置。

打开项目时：

- 精确匹配配置版本。
- 配置版本升级时保留旧设置并提示迁移。
- 配置缺失时进入通用模型并明确提示，不能修改项目原值后静默保存。

## 13. 代码冗余控制

本轮改版不能在旧大型脚本中复制新逻辑。

执行原则：

- 3D、导入、项目存储、工作空间 UI 和输出分别建立清晰模块。
- 同一功能只有一个数据源和一个渲染入口。
- 旧材质预览保留兼容入口，但不得复制一套新的相同控制状态。
- 新 3D 预设与旧 `materialModeSelect` 通过显式迁移映射连接，不能共享含义不一致的字符串值。
- 逐步把 `web/app.js` 中可独立的纯函数迁出，并先增加回归测试。
- 每次功能提交必须同步本地工作区与 GitHub 仓库；发布前验证本地 App 的构建来源与 Git 提交一致。

## 14. 验收标准

### 14.1 UI 与交互

- 桌面编辑器固定布局在 1180 px 以上无横向溢出。
- 平板布局不依赖浏览器缩放才能操作。
- 所有弹窗和抽屉均可滚动、可关闭、可由键盘退出。
- 阶段切换不改变画布缩放、平移和选区。
- 高频触控目标不小于 44×44 CSS px。

### 14.2 图纸重建

- 截图、拍照图纸和 PDF 单页可进入正确流程。
- 自动校正失败时可手动拖动四角和网格线。
- 低置信度格子集中审核，不要求逐格确认高置信度内容。
- 取消、失败和返回不会覆盖原项目。
- 应用后可从检查点恢复。

### 14.3 3D 实物一致性

- 几何尺寸误差不超过约 0.2 mm。
- 孔径和熔融面积与标准样片偏差不超过 5%。
- 标准拍摄条件下主要颜色平均色差目标为 ΔE00 ≤ 3。
- 闪片、镭射和高光随镜头/灯光方向变化。
- 近景孔洞、连接桥和熔融边缘必须是真实几何或可信位移，不是固定二维贴图。
- 十种预设均保留正面、侧面和背面实拍参照。
- 屏幕预览与 4K 导出使用同一渲染配置。

### 14.4 性能与稳定性

- 覆盖小图、万颗级作品和 500×500 极限图纸。
- 覆盖桌面与平板目标设备。
- 覆盖快速旋转、连续缩放、预设连续切换和窗口变化。
- 覆盖离线冷启动、前后台恢复、WebGL 上下文丢失和显存压力。
- 3D 失败不影响项目保存、编辑和导出普通图纸。
- 4K 导出可取消，失败可重试，且不产生半成品项目状态。

### 14.5 自动测试

- 纯函数：邻接关系、实例数量、LOD 选择、配置迁移、标定状态。
- 视觉基准：固定项目、相机、灯光和十种预设的参考图。
- 像素差异：允许抗锯齿小波动，但检测模型缺失、纹理未加载、颜色空间错误和灯光方向错误。
- 性能基准：记录首帧时间、稳定帧率、峰值纹理/几何数量和 4K 导出耗时。
- 错误注入：缺少纹理、损坏配置、上下文丢失、导出取消和内存不足。

## 17. 最终产品原则

Q像素 2.0 的竞争力不是堆叠更多按钮，而是把图纸获取、专业编辑、真实配色、实际拼制、可靠输出和写实成品验证连接为一个稳定流程。

任何新功能都必须满足：

- 可发现。
- 可跳过。
- 可取消。
- 可撤销或恢复。
- 不阻塞本地工作。
- 不以未验证的视觉效果冒充真实结果。
