# Q像素作品可靠性专项设计

日期：2026-10-09（北京时间）  
状态：四项范围已获用户确认；本文件为待用户审阅的具体设计，尚未实施。

## 1. 目标与已确认边界

用户始终知道作品保存在哪里，退出后能继续，跨端修改不会静默覆盖。

范围包括保存状态、服务端并发保护、本机作品库批量备份与迁移、三端实际验收。继续使用本机离线保存与主动点击“同步电脑文件”。网络恢复、保存、导入和更新不触发上传。跨网络、Tailscale、CloudKit、3D 和制作流程改版均不属于本轮。

## 2. 现状依据

- `web/core/offline-projects.js` 已将正文、索引和待同步修订放入同一 IndexedDB 事务，并防止旧同步确认清除新修改。
- `web/core/auto-draft.js` 保存恢复草稿和历史，但位于另一数据库；作品库备份必须读取两处。
- `web/app.js` 顶部仍用“未保存／保存中／已保存”；卡片已有“本机已保存·待同步”“可离线打开”“尚未下载到本机”。同步错误当前经常统一显示为电脑未连接。
- 服务端单作品写入按时间戳接受更新。`WRITE_LOCK` 能串行处理服务端写入，但没有原子核对客户端共同版本。批量 POST 和 DELETE 也必须覆盖。
- `.qpx` 目前导出当前画布，不是整个作品库；已有入口迁移引导要求逐作品操作。
- 2026-10-02 的 QA 提供桌面 Chromium 离线、回读与冲突证据，明确不等同真实 iPad 或原生 App 验收。本轮不沿用历史结果作为新验收。
- 本次读取的安装包为 2.0.0/build 60；工作区另有备料、迁移及样式改动。实施前重新核对并保护这些修改，不把它们归入本专项提交。

## 3. 方案比较与推荐

1. **推荐：沿用本机优先架构，补版本条件写入和独立作品库备份。** 可复用现有持久化、草稿和同步队列，直接覆盖已确认风险；需要客户端、服务、代理和包版本协同验证。
2. 只增强提示与逐作品备份：改动较小，但并发覆盖窗口和迁移成本仍存在，无法满足本轮验收。
3. 重建云端统一作品库：可另行研究跨网络体验，但引入账户和服务依赖，超出本轮已确认范围。

## 4. 保存与同步状态

两条状态独立展示，不将草稿、下载请求或历史确认当成当前作品保存成功。

| 本机状态 | 显示条件 |
| --- | --- |
| 未保存 | 当前编辑修订尚未成功提交作品事务 |
| 保存中 | 当前修订正在提交；其间继续编辑仍保持未保存状态 |
| 已保存到本机 | 当前编辑修订事务已完成，显示最近成功保存时间 |
| 保存失败 | 事务失败，保留当前画布和未保存标记，提供重试与当前 `.qpx` 备份 |

| 电脑状态 | 显示条件 |
| --- | --- |
| 待同步 | 本机存在未获电脑确认的修订，包括删除记录 |
| 同步中 | 用户启动同步，显示已处理及待处理数量 |
| 已同步 | 当前已保存修订获得条件写入确认及内容核对，且没有更新修订待发送 |
| 同步未完成 | 网络、配对、版本、服务写入或回读失败；按实际原因提示，队列保留 |
| 存在冲突副本 | 双方内容已保留，提供原稿和副本入口；不得表达为内容已合并 |
| 尚未下载到本机 | 仅有索引，不能显示可离线打开 |

未保存画布与已同步旧版本并存时，显示“当前修改未保存；上次保存版本已同步”。恢复草稿只提示“发现可恢复草稿”；恢复进入未保存画布，待用户保存。相同修订无需重复写入时可保留已同步状态。

状态从编辑修订、本机事务和同步队列推导。保存、备份和同步使用不同成功事件。原生文件写入回调必须关联具体请求；取消文件保存不显示备份成功，也不清除画布未保存状态。浏览器只能显示“已发起下载，请确认文件已保留”，不能声称文件已经落盘。

## 5. 原子版本保护

### 5.1 协议

- 服务端为每个作品提供不透明 `serverRevision`，GET 正文和索引包含该版本，客户端存入共同基线。版本由服务端产生，不依赖设备时钟。
- 新记录原子创建时生成版本；旧记录由服务端对持久记录计算稳定版本，首次成功修改后写入新的随机版本。客户端不自行推算版本。
- 更新与删除携带 `expectedRevision`；创建明确声明预期不存在。服务端在同一写锁内读取、核对并写入，不使用时间戳决定覆盖。
- 缺少写入条件返回 428；版本不匹配返回 409 和当前版本，不写入。旧客户端保持可读，写入时提示保存或备份后更新，不允许绕过保护。
- 批量旧接口禁止无条件写入；本轮客户端逐作品条件写入。已接受作品保留结果，失败作品留队列，不宣称整批原子成功。
- 代理完整传递条件、状态码和响应；服务能力声明协议版本。新客户端遇到旧服务停止上传并提示服务更新，不退回时间戳写入。

### 5.2 重试与冲突

- 每次待发送修订绑定稳定 mutationId；服务端在作品记录中保存最后一次接受的 mutationId 和请求摘要。相同请求重试返回原确认，不生成第二次修改；同 ID 不同请求拒绝。
- 服务端提交成功但客户端未收到响应时，重试或回读核对；仅确认实际发送修订，之后的新编辑继续待同步。
- 409 后读取新版本，保存本机冲突副本，原稿不覆盖。副本 ID 稳定，重复同步不制造重复副本。
- 上传前检查可改善提示，上传后回读可发现异常；二者不替代写入时的条件核对。

### 5.3 删除与持久化

- 回收站删除与恢复属于条件更新。永久删除同样要求当前版本；远端已改变时保留本机删除队列并提示核对。
- 永久删除将持久作品记录原子替换为仅含 ID、版本、删除状态与重试信息的墓碑，不保留正文。正常列表隐藏墓碑、正文 GET 返回 404；条件接口仍识别删除版本。
- 墓碑在本轮不自动清除，防止旧离线客户端以“预期不存在”复活原 ID。恢复备份中的同 ID 作品使用新 ID，不撤销电脑的永久删除。
- 正文与版本存于同一原子替换文件；索引是可重建缓存。索引失败不得丢正文或版本；重启重建后保持相同并发保护和幂等结果。
- 本轮支持现有单权威写服务与只代理的平板服务；启动时阻止多个权威写服务并用同一数据目录，不以进程内锁宣称多进程安全。

## 6. 作品库批量备份与迁移

### 6.1 格式和范围

沿用单作品 `.qpx`；增加版本化 JSON 作品库文件 `.qpxlib`，使用现有文件导出通道，不引入 ZIP 解压依赖。内容包括清单、格式版本、导出时间、逐项校验摘要、完整作品记录、实际可读历史、回收站正文及一份实际存在的恢复草稿。

- 保留正文中的图层、色号、拼制进度、预览设置及已嵌入参考资源，不过滤陌生合法字段；格式兼容与字段检查由项目模型处理。
- 正在编辑的未保存画布单独作为恢复草稿保存，不自动覆盖已保存作品，也不伪装为本机保存成功。
- 包含删除状态和来源待同步信息用于核对；不导入旧服务器版本、旧设备的上传凭据或可直接执行的删除队列。
- 不含配对密钥、账号令牌或原设备路径。来源标签供用户识别，不能赋予目标入口跨地址存储访问能力。
- 只有远端索引的作品列入“未包含正文”清单，不自动下载。历史不可读也单独列出。存在遗漏时名称和提示明确为部分备份，不显示“完整备份”。

### 6.2 一致性和容量

- 开始前暂停本页面草稿与作品写队列并等待完成；读取后核对作品修订、索引集合和草稿摘要。跨页面变化时中止本次生成，提示关闭其他编辑页后重试，不能输出混合版本备份。
- 导出完成恢复队列，不改变保存状态、待同步状态和作品内容。整库备份不截断作品数量。
- 首版单包最多 1000 条作品记录，输入文件及生成内容不超过 50 MiB UTF-8 数据；预估超限或设备内存不足时停止并支持选择子集分批备份，不静默丢弃。
- 校验摘要采用 SHA-256；用于发现损坏，不表示文件来源可信。

### 6.3 导入行为

1. 解析、版本检查、逐项校验和引用检查全部在写库前完成；显示可导入、重复、冲突、历史、草稿及缺少正文数量。
2. 同 ID 且完整内容相同的记录跳过。内容、历史或删除状态不同的记录导入为新 ID 副本，更新内部引用并记录来源 ID，不覆盖目标原稿。
3. 回收站正文保留在目标回收站，不自动恢复为活动作品。永久删除墓碑只记录在迁移报告中，不向目标电脑发送删除。
4. 恢复草稿导入为独立“恢复草稿”作品副本，避免覆盖目标已有恢复草稿或当前画布。
5. 活动导入作品保存后加入目标待同步队列；同内容跳过项保留目标原状态。回收站导入记录不加入上传队列，用户恢复后才作为待同步作品。
6. 作品、历史和报告先暂存，不修改正常库；所有校验通过后，在作品库同一事务提交导入记录、索引、待同步项及可恢复的历史待迁移数据。草稿历史库通过幂等步骤接收历史，在完成前从已提交暂存历史读取。重启可继续，不出现有索引无正文或历史丢失。
7. 导入取消或事务失败不影响原库；错误文件允许查看错误并导入明确选中的有效子集，必须重新确认子集结果，不静默跳过损坏内容。
8. 导入结果列出新增、跳过、副本、回收站、草稿和遗漏项目；允许下载报告。导入不替换当前画布、不自动上传。

## 7. 实施模块与顺序

按三个可独立验证的阶段交付：A 保存状态与全入口版本保护；B 批量备份迁移；C 三端验收和发布收口。每阶段验证后再进入下一阶段，不捆绑其他功能改动。

- 保存状态模型独立模块：只从当前修订、持久化结果和队列生成展示状态。
- 同步协议适配：复用 offline-projects，新增服务端版本基线和幂等请求；不复制旧同步逻辑。
- 作品库备份模块：负责解析、校验、规划和摘要，不直接操作当前画布。
- 迁移存储模块：负责暂存、原子提交和历史幂等迁移。备份数据不得执行代码或作为 HTML 注入。
- 服务端条件写入统一入口覆盖创建、更新、回收站、恢复及永久删除。
- 修改原生导出桥，仅为请求关联、写入成功和取消反馈服务。新核心模块同步登记构建和发布验证清单。

## 8. 验收矩阵

| 范围 | 必须覆盖的用例 |
| --- | --- |
| 保存 | 新作身份稳定；保存期间继续编辑；事务失败；草稿失败；存储空间不足；关闭重开后核对正文 |
| 同步 | 同基线双端修改；乱序；不同设备时钟；响应丢失重试；服务重启；回读失败；同步中继续编辑；409/428 分类提示 |
| 删除 | 删除与远端修改竞争；永久删除与创建竞争；重复删除；重启后墓碑仍阻止复活；备份恢复另存新 ID |
| 迁移 | 超过原历史数量限制的作品库；多层与全色号；拼制进度；相同 ID；历史与草稿；回收站；未下载索引；损坏摘要；超容量；取消和中途失败 |
| 三端 | macOS WKWebView、电脑浏览器、真实目标 iPad 分别执行编辑→保存→退出→重开→继续拼制→手动同步 |
| 移动端 | 离线冷启动；后台恢复；触控操作；浏览器/PWA 文件下载与导入；配对失效；入口变化后按备份迁移 |
| 发布 | 聚焦回归、npm test/build、diff check、发布校验、安装资源 SHA256 与 release-info、服务及缓存版本核对 |

小图、万格图纸和 500×500 双图层图纸分别验证；不能只用合成小图推断极限或实际设备表现。网络恢复、保存和导入的项目写请求计数必须为零，手动同步才产生写请求。

全部破坏性检查使用独立 QA 数据目录、数据库和作品，保护现有用户作品及未保存页面。用户自己的配对或设备解锁步骤由用户完成。真实 iPad 不可用时明确标记“待验收”，不能宣告三端完成。

## 9. 证据与指标

每阶段记录源码提交、协议版本、测试环境、样本、实际结果、安装包版本与未验收项。安装/本机服务更新与公开发布分别记录，不以当前源码代替已交付功能。

首轮由隔离 QA 报告统计：本机保存并完整重开成功数/用例数；手动同步后打开正确版本并再次保存成功数/用例数；迁移后正文与历史核对成功数/迁入数。并发覆盖与假报成功用例必须零失败。

这些是工程验收指标，不当作真实用户完成率。线上行为指标和外部分析服务不在本轮；后续取得实际使用数据再建立用户层面的基线。
