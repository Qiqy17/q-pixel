# Q像素界面与成品材质重构设计

日期：2026-09-23
状态：设计方向已确认；待用户复核本规格后实施
适用：本地 Web、macOS App、平板浏览器

## 1. 目标与既有决策

本规格修正 Q像素 2.0 build 8 的首页、工作台、展示预览和成品 3D 预览。它不追加无关功能，不以新视觉掩盖不可用操作。

用户已选择：

1. 首页采用内容优先的“作品工作台”，作品与文件夹先于宣传内容。
2. “展示图”和“成品质感 3D”分离：前者安排展示场景，后者模拟豆体与烫法。
3. 撤掉全宽工作阶段栏，改为有呼吸感的顶部模式切换；保留画图、配色、拼制、导出的真实能力，版本收进项目菜单。
4. 材质依据使用公开可访问的实拍、品牌资料与教程；无同条件 MARD 5 mm 实物照片时，明确标“未实物标定”。

本规格覆盖四个可独立验收的工作包：A 首页/编辑器信息架构，B 展示图预览，C 成品质感 3D，D 真实图像材质参考库。按 A、B、D、C 的依赖顺序交付，但最终发布必须一起通过回归；某一包没有证据时不得借其他包的完成状态宣称整体写实完成。

## 2. 现状证据与关键问题

- `web/index.html` 的首页有占据首屏的大 Banner、重复的创建入口和四张流程卡；项目列表下沉。首页和编辑器标识使用不一致。
- `web/index.html` / `web/styles.css` 的全宽 `workflow-stagebar` 不是纯装饰：`web/app.js` 的 `applyStudioStage()` 控制阶段面板和拼制模式。重构只能移动入口，不能直接删除行为。
- `web/app.js` 的 `drawMaterialPreview()`、`surfaceEngine` 会在图案上叠加材质纹理；某些模式令豆子颜色丢失、趋于一致。
- `web/3d/finish-viewer-entry.js` 目前所有色号共用一个 `MeshPhysicalMaterial` 和一个豆体实例网格；透明豆无法拥有独立的透射/折射策略。烫法主要改变简单车削轮廓、粗糙度与方条连接桥，不能反映真实熔融边界。
- `web/3d/finish-core.js` 明确标为通用模型，十个 profile 的高度和孔径不是 MARD 样片实测值；不得将其称为 MARD 标定成果。

以上事实以当前仓库为准；变更前后都要保留稳定默认路径与开启专业工作区的回归检查。

## 3. 产品原则与范围边界

每个可见控件必须回答“执行什么动作、何时使用、结果在哪里”。无动作价值的日历、口号、阶段提示和重复按钮移除或收进相关上下文；可用的保存、恢复、拼制、导出不删。

本轮不做：社交功能、云端材质识别服务、自动爬取需要登录或禁止抓取的平台、无版权依据的第三方照片内置、以 AI 生成图冒充真实样片、未实测的温度/时间/压力预测。背景去除与已有图纸重建等既有功能保持可达，但不是本规格的新功能开发范围。

## 4. 首页与编辑器

### 4.1 首页

- 顶部统一使用 `web/icon.svg` 的品牌标识及同一命名；不再出现旧网格图标。
- 移除占据数百像素的纯装饰 Banner、重复的四张流程卡及无关“我的”日历卡。
- 首屏主体是“创作空间”：最近作品网格、搜索、排序、文件夹和继续编辑；保留缩略图失败时的品牌占位图。
- 一个短的功能性引导区只保留“导入图片”；图片转图纸、重建已有图纸、参考描绘、空白画布入口在快捷任务区各出现一次，文案解释产物差异。
- “新建设计”可以打开任务选择，不与快捷任务区产生另一个不同实现的创建逻辑。
- 1440×900 常规窗口中无需滚动即可看到至少一行作品；无项目时提供同位置的空状态和一个明确创建动作。

### 4.2 编辑器

- 顶部两类内容视觉分组：项目/状态、四个模式切换、保存/预览。桌面留足组间空白，不把所有元素压在同一小按钮簇。
- “画图、配色、拼制、导出”仍调用已有阶段行为。版本入口迁至项目菜单，恢复和检查点仍在可见的项目安全区域可达。
- 移除全宽阶段条及无操作结果的阶段介绍。只有发现可处理问题时，右侧上下文栏显示可点击直达的检查提示。
- 左侧工具区和右侧属性区只显示当前任务相关控件；画布始终是主体。保存状态、撤销和拼制进度在对应任务中保持可见。
- 768–1179 CSS px 平板宽度允许顶部模式换行、属性抽屉覆盖显示，不能让画布被永久双侧栏夹窄；触控目标不低于 44×44 CSS px。
- 任何弹窗和抽屉在 820×1180、1024×768、1440×900 下可关闭、可滚动、无横向溢出；键盘焦点与返回键行为保持正确。

## 5. 展示图预览

“展示图”只负责作品在场景中的呈现：背景、位置、比例、边框、投影、导出。豆体外观由 3D 材质工作台决定，展示图不得把统一白色/珠光遮罩覆盖整件作品。

- 预设从当前平面色块扩为至少六种真实感场景：暖灰石膏、浅橡木、亚麻织物、深色石材、牛皮纸、真实底板。背景资源需有来源、许可、版本和缩放策略；无法合法内置时用可重复生成的摄影级 PBR 纹理，不能借用网络照片打包。
- 预设只改变背景与匹配的环境光/接触阴影，不改变原图色号；“无背景/透明”保持可选。
- 当前大量不可信遮罩、重复边框与无意义滑杆要按真实使用价值清点：没有稳定可感知结果的选项删除；保留选项提供即时预览、重置与导出一致性。
- 强弱调节必须有可见效果且有合理默认值；避免多个滑杆做同一件事。
- 切换预设、缩放、取消、自定义背景失败时不污染源工程；导出结果与预览一致，源图颜色不发生意外漂移。

## 6. 成品质感 3D

### 6.1 渲染分层

采用“几何结构 → 树脂光学类别 → 烫法表面 → 环境照明”的四层模型。原因：当前单一网格/单一材质不能兼顾纯白和透明，单独增加纹理也无法让烫法结构真正不同。

1. **几何结构**：豆高、外径、孔径、顶面圆角、侧壁、相邻融合边界、正反面。弱化当前显眼的长方体连接桥，使用接触处局部融合的形状或贴合边缘；按性能档位降低细分，但保留主要孔洞差异。
2. **树脂光学类别**：从品牌色卡元数据标记不透明、半透明、透明和特殊效果；纯白是不透明且有漫反射的树脂，透明豆使用独立材料组与透射/边缘高光，不靠把白色调淡。未知色号默认不透明并明确提示。
3. **烫法表面**：微法线、粗糙度、局部光泽和压印方向只作用于豆体表面，纹理比例以豆径为基准；不把同一张素材铺在整个图案上。
4. **环境照明**：同图案、同视角、同光照对照烫法；展示场景不参与材质校准。允许正面、背面、斜侧面切换并观察实际高度和孔洞。

### 6.2 十种状态的可辨识规则

| 状态 | 必须出现的主要差异 |
| --- | --- |
| 未烫 | 完整圆柱/管状高度、开孔和分离的豆体顶缘 |
| 轻烫 | 孔仍明显，顶缘略软化，相邻接触有限 |
| 标准 | 孔可见但变窄，接触处融合，正反面可区分 |
| 完全平融 | 正面孔近乎闭合，面更连续、边界摊开；不能只整体压扁 |
| 背熔 | 展示面保留立体孔和轮廓，背面融合明显增强 |
| 毛巾 | 表面产生细密随机纤维压痕，不在背景上贴毛巾图 |
| 澡巾 | 与毛巾不同的较粗、方向性网纹/颗粒压痕 |
| 华夫格 | 可感知的正交格纹压印，尺度与豆顶相符 |
| 闪片 | 离散的片状高光随视角变化，不把所有颜色变银白 |
| 镭射 | 角度相关的薄膜干涉色，正面色号仍可辨认 |

后六类由表面媒介和热量共同决定，不能被表述为固定温度的唯一效果。对没有可靠实拍证据的组合保留“参考模拟”说明，不伪造精确参数。

### 6.3 性能与交互

- 3D 仍为可旋转、可缩放、可拾取的真实几何预览；“写实”不等于播放一段预录动画。
- 不透明与透明分组实例化；透明数量巨大时通过 LOD、减少透射采样或低成本替代保障交互，且提示画质档位。
- 只在用户操作或设置变化时渲染；预设切换避免整页长时间无响应。GPU 上下文丢失、导出取消和内存不足均有可恢复状态。
- 保留 4K 导出能力，但先保证互动预览正确；导出与屏幕使用同一材质定义，不能一边真实一边失真。
- MARD 5 mm 与其他品牌均显示校准状态。未取得实物尺寸和受控样片前，MARD 也标“未实物标定参考模型”；不得用 Perler 的测量值冒充 MARD。

## 7. 真实材质参考库与数据流

### 7.1 来源和采集

第一批覆盖十个状态，每状态优先找正面、斜侧面、背面和有尺寸参照的近景；另采集纯白、透明、深色豆以比较光学响应。采用公开可访问的品牌官方图、用户公开实拍、教程/视频帧、开放许可摄影资料。平台条款、版权与可访问性优先于样本数量；不绕过登录、防抓取或水印，不把未获授权的第三方原图打入 App。

每条记录保存：原始 URL、作者/平台、访问日期、烫法和品牌声明、许可状态、视角、光源、压印媒介、尺寸参照、是否经过后期处理、可用于哪一类判断。图片仅在许可允许时保存在仓库或发布包；其余保留链接与人工标注数据。失效链接不影响 App 运行。

### 7.2 数据质量

- A 级：品牌/原作者来源，工艺明确，同图案或有尺度参照，多视角；可校准相对形态。
- B 级：工艺可信但光线/相机未知；只用于趋势与纹理特征。
- C 级：平台说明不完整或重度滤镜；仅启发，不参与参数拟合。
- D 级：来源不明、合成图或转载链断裂；剔除。

不同光照照片不做直接颜色取样。先标注孔洞占比、顶面平整度、熔接面积、侧壁高度趋势、纹理周期/方向、反射与透光类别，再拟合程序化几何和 PBR 参数。每一版记录“参考源 → 参数变化 → 对比截图 → 人工评审结论”，让优化有可追溯依据。只有同批 MARD 实物测量和受控摄影才可以把状态改成“实物标定”。

初始物理依据：[Perler 标准熨烫说明](https://perler.com/blogs/projects/standard-fusing-method)指出标准融合仍有开孔；[Perler 官方 FAQ](https://perler.com/pages/frequently-asked-questions)说明热量和压力会影响孔洞闭合。二者证明形态变化方向，但不能给出 MARD 的数值。公开[烫法图例](https://www.pixelbeads.io/zh-cn/blog/how-to-iron-perler-beads)与[真实作品视频](https://www.douyin.com/video/7611524955252156288)用于寻找纹理和融合状态，具体图片逐条评估可信度。

## 8. 代码边界与迁移

- 首页/导航视图与事件映射从 `web/index.html`、`web/styles.css`、`web/app.js` 的现有机制渐进调整；不再新增一个平行的首页/阶段状态源。
- 展示图预览保留当前导出数据接口，但将背景场景、阴影/排版与豆体外观拆分；旧设置需要安全降级映射，未知旧材质值不阻止打开项目。
- `finish-core.js` 只存 profile 定义、校准状态、几何参数约束与纯函数；渲染器负责网格/材质/相机/性能。色卡的光学类别取单一注册表，不在渲染器再写一份色号列表。
- 参考库元数据与渲染参数分离。样本 URL 不作为运行时依赖；离线 App 不联网也能正常预览。
- 禁止把新的样本分析和材质分支继续塞入大型 `web/app.js`；新增清晰的渲染/场景模块并维持现有入口兼容。

## 9. 验收与发布

### 功能与视觉

1. 首页 1440×900 首屏看见一行项目；820×1180、1024×768 无横向溢出、创建/搜索/继续编辑可点击。
2. 首页与编辑器使用同一 logo、色彩、圆角、图标规格；无装饰 Banner、重复入口和无用日历。顶部有可感知的组间空白。
3. 四模式全部可操作；拼制进度、版本/恢复、保存、导出原有能力仍可达。键盘与触控可用。
4. 展示图六种背景确有不同材质表现；切换背景或边框不会让原豆子颜色变白。透明导出背景正确。
5. 十种 3D 烫法在同一图案、同一相机和灯光下留下对照截图；未烫/轻烫/标准/平融/背熔的孔洞和高度变化可辨，四种纹理/特效随视角合理变化。
6. 纯白与透明豆在浅、深两种背景中可区别；正反面、斜侧面可检验高度；颜色与色号保持一致。
7. 样本参考库每个进入参数评审的条目有来源与可信度；无未授权图片进入发布包；MARD 未测状态正确显示。

### 技术回归

- `npm test`、`npm run build`、默认 `/test.html` 和专业功能参数路径分别通过；新增几何/材料纯函数测试和浏览器截图回归。
- 典型 30×30、较大 120×120 和极限 500×500 图纸分档测预览启动、交互及导出；极限规模可以降画质，但不能锁死编辑和取消操作。具体性能数字记录设备、浏览器、分辨率，不在未经实测前承诺帧率。
- Web 桌面、平板尺寸、已安装 macOS App 逐流程验收；构建后运行 `scripts/verify_release.sh`，核对 App 资源/版本与 Git 提交一致，并同步本地与远端仓库。未在真 iPad 或实物上验证的项目明确标“待确认”。

## 10. 发布口径

只有当代码、网页、安装版 App 和 Git 仓库同步，且第 9 节测试完成，才能说“本轮界面/材质改版已交付”。即便完成参考库和写实向渲染优化，在取得 MARD 5 mm 受控实拍及测量前，也只能称“参考级写实预览”，不能称“MARD 实物标定完成”。
