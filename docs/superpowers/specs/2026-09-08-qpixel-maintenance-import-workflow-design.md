# Q像素代码维护、导入流程与本地发布设计

日期：2026-09-08

## 目标

本次改造同时解决四类问题：

1. 删除已经确认的重复、不可达和无调用代码，并移除当前前端未使用的 8765 旧同步服务。
2. 补齐仓库直接运行、离线缓存和 macOS App 重建所需文件。
3. 建立可重复、可校验、可回滚的 macOS App 构建与本地安装流程。
4. 将强制出现的导入优化向导改为可选流程，并完善响应式布局、状态隔离、色号约束和自动化测试。

Git 仓库是唯一源文件真源。每次交付必须同时完成仓库提交、GitHub 推送、本机 App 重建、资源一致性校验和运行验证。

## 已确认的产品决策

### 图片导入入口

选择图片后先显示一个轻量入口，而不是立即进入完整优化向导：

- **快速导入，直接编辑**：自动估算像素网格并生成一次可编辑结果；不强制执行色号压缩、智能修复、校准或锁色。
- **进入高级优化**：进入完整四步向导，自主选择导入模式、像素精度和色号限制。

图层图片导入沿用相同入口。快速导入时直接转换为匹配当前画布尺寸的新图层；高级优化时在临时状态中生成图层，确认后再写入画布。

### 完整向导布局

采用 A1“响应式居中工作台”：

- 桌面宽屏使用预览区和设置区双栏布局。
- 平板竖屏和窄屏自动切换为单栏布局。
- 弹窗最大高度使用动态视口单位，避免浏览器地址栏和缩放造成内容截断。
- 标题、步骤状态和操作栏保持可见；中间内容区独立滚动。
- 所有按钮满足触控尺寸，预览画布按容器缩放而不是撑大弹窗。
- 每一步提供“使用当前结果并进入编辑”，完整向导不再是必选项。

## 导入状态与数据流

### 会话隔离

每次图片选择创建唯一导入会话标识。图片读取、网格估算、AI 辅助分析、校准预览和色号优化回调都必须校验当前会话标识；旧会话回调不得覆盖后来选择的图片。

导入期间只修改临时向导对象，不直接修改当前作品。只有用户选择“快速导入”“使用当前结果并进入编辑”或最终“应用到当前图纸”时，才把临时结果提交到编辑器状态。

取消导入时应：

- 撤销临时锁色和角色分析结果；
- 恢复重新校准前的校准数据；
- 释放不再使用的 Blob URL；
- 保持当前画布、历史栈和未保存状态不变。

### 快速导入

快速导入执行以下最小流程：

1. 读取图片并校验类型及有效尺寸。
2. 在有限采样尺寸内估算像素网格。
3. 按当前模式生成像素画或拼豆图纸；图层导入则匹配当前图纸尺寸。
4. 重置与旧图片绑定的校准、恢复指纹和锁色信息。
5. 进入编辑器并标记为未保存。

快速导入不会自动减少色号，也不会运行主体清理、断线修复或对称修复。

### 高级优化

高级优化保留四个阶段：识别、精度、色号、确认。用户可在任何阶段提交当前可用结果；如果该阶段尚未生成图纸，提交动作先使用当前设置生成一次图纸。

处理按钮在异步任务期间进入忙碌状态，阻止重复点击，并显示正在执行的具体操作。失败时保留当前临时结果，给出可恢复的错误信息，不自动关闭向导。

## 导入优化修正范围

### 色号上限

“最多色号”表示最终图纸的总色数上限，而不是“普通颜色上限再额外保留锁色”。当保护色数量超过限制时，按轮廓、关键高光、使用量的优先级保留不超过上限的保护色，其余颜色参与合并。

确认页显示优化前色数、优化后色数、被保护色数和发生变化的单元格数量。结果超过用户上限时视为失败，不允许静默进入确认页。

### 预览与大图处理

原图和图纸预览保持相同的可视区域比例，并使用容器尺寸进行 CSS 缩放。用于分析和预览的中间画布限制最大边长，原始图片对象仍保留给最终采样，避免大图在小屏浏览器中占用过多内存。

### 生产界面与测试一致

回归测试不得依赖与生产页面文案不同的伪造按钮。测试夹具使用与生产页面相同的入口、按钮标识和步骤结构，并增加以下路径：

- 快速导入跳过完整向导；
- 从识别、精度、色号阶段分别提交当前结果；
- 取消导入后恢复原作品状态；
- 连续选择两张图片时旧回调失效；
- 色号优化结果严格不超过上限；
- 宽屏、平板竖屏和手机宽度下操作栏可见且内容可滚动。

## 代码去重与服务整理

### 前端

删除以下明确冗余：

- 被后一个同名声明覆盖的旧版 `drawMaterialPreview`；
- 已从 HTML 移除的挂件预览实现和事件绑定；
- 没有任何引用的辅助函数；
- 已被新导入路径替代的旧函数，仅保留并重命名仍用于快速导入的实现。

本次不全面拆分 14,000 行前端文件，避免在修复导入流程时引入无关的大范围回归。后续模块化应单独设计。

### 本地服务

当前网页和 macOS 外壳统一使用 8766。删除未被当前前端引用的 8765 服务脚本及其启动项，避免两个进程维护同一数据目录。

8766 继续同时提供静态资源、项目同步、设置同步和 AI 代理接口，并增加进程内写锁。项目索引、项目文件、设置和备份的修改必须在同一个锁保护区内完成，临时文件使用原子替换。

本次不改变局域网访问协议和认证方式，避免未经单独产品设计就破坏现有平板连接。网络访问控制作为后续独立安全任务处理。

## 仓库缺件修复

将唯一图标源放在 `web/icon.svg`，使 README 中的静态服务器启动方式、Manifest 和 Service Worker 使用同一路径。删除原来位于 `assets/` 的重复图标。

仓库新增并跟踪：

- 8766 LaunchAgent 模板；
- macOS App 构建脚本；
- 本地安装与校验脚本；

构建脚本只从已跟踪源目录收集明确列出的生产文件，不复制测试页面、测试图片、源码副本、Python 缓存、旧二进制和临时文件。

## macOS App 构建与安装

### 包结构

构建结果使用标准目录：

- `Contents/MacOS/QPixel`
- `Contents/Resources/` 生产网页和服务资源
- `Contents/Resources/AppIcon.icns`
- `Contents/Info.plist`

`CFBundleIdentifier` 固定为 `local.qpixel.app`。版本号和构建号由构建脚本参数控制，并写入 `Info.plist`。本次版本使用新的语义版本和递增构建号，不沿用旧的 `1.0 (1)`。

### 图标与签名

构建脚本由仓库中的 SVG 生成标准 `.icns`。本机当前没有可用的 Developer ID 身份，因此默认生成可通过 `codesign --verify --deep --strict` 的 ad-hoc 本地签名。

脚本支持通过环境参数传入正式签名身份；正式跨设备分发仍需 Apple Developer 证书和公证，本次不宣称已完成公证。

### 安装与回滚

安装流程先在临时目录完成构建、语法检查、签名检查和资源清单校验。全部通过后：

1. 将旧 App 复制到带时间戳的备份目录；
2. 停止旧的 8765、8766 启动项；
3. 原子替换桌面的 `Q像素.app`；
4. 安装并启动新的 8766 LaunchAgent；
5. 验证健康接口、首页、Service Worker 和浏览器回归页；
6. 验证生产 App 不含禁止文件。

任何校验失败都不替换当前 App。替换后的运行验证失败时恢复最近一次备份。

## 本地与 GitHub 同步规则

每次 Q像素代码交付遵循以下顺序：

1. 检查工作区，确认没有不属于本次任务的改动。
2. 运行 JavaScript、Python、Swift 和浏览器回归测试。
3. 构建并校验临时 App。
4. 更新本机 App 和 8766 服务。
5. 再次验证本机运行状态及源码资源哈希。
6. 提交本次源文件、测试、文档和构建配置。
7. 推送当前分支到 GitHub。
8. 比较本地 `HEAD`、远端 `main` 和本机 App 发布清单中的提交标识。

发布脚本遇到无关脏文件、测试失败、签名失败、资源不一致或远端推送失败时必须停止并明确报告，不得把本地与 GitHub 描述为已同步。

## 验证标准

完成条件包括：

- 仓库和在线 `main` 指向同一提交；
- 工作区干净；
- JavaScript、Python、Swift 检查通过；
- 浏览器回归页返回 `PASS`；
- 三种目标视口下导入入口和完整向导无需缩放即可完成操作；
- 快速导入不进入完整向导；
- 高级优化可在任意步骤提交当前结果；
- 色号结果不超过设定总数；
- 8766 健康检查通过且项目数量与独立文件数量一致；
- 8765 不再监听；
- App 严格签名校验通过，包标识与 `Info.plist` 一致；
- App 不包含测试资源、源码副本、缓存和备份二进制；
- 本机 App 中的生产资源与仓库对应文件 SHA-256 一致；
- 旧 App 备份和发布清单存在，可用于回滚。

## 非本次范围
