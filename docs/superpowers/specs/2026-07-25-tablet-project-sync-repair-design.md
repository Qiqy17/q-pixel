# Q像素平板项目同步修复设计

## 目标

让电脑网页、桌面应用和平板网页通过同一个本地服务可靠同步设计文件，避免大索引拖慢平板，也避免已有旧缓存阻止新版正文下载。

## 数据流

- `/api/projects/index` 只返回项目元数据、缩略图、正文大小和历史版本数量，不返回当前正文或历史正文。
- 浏览器本机项目索引同样不保存历史正文；检测到旧格式时自动压缩为轻量索引。
- 打开设计、导入图层、复制设计时，客户端按需请求 `/api/projects/:id`。
- 客户端记录本地正文对应的更新时间和远端索引更新时间。远端更新更晚时，打开文件前重新下载正文。
- 历史版本列表首次打开时按需读取完整项目，之后使用本地缓存。

## 冲突与离线保护

- 同步成功后，把当前正文指纹记录为同步基线。
- 双端都从同一基线产生不同正文时，继续使用现有策略：保留较新版本，并生成冲突副本。
- 远端暂时不可访问时，仍允许打开本机缓存，不删除或覆盖本机内容。

## 兼容性

- 旧项目缺少正文时间戳时，以项目保存时间作为初始值。
- 服务端同时更新 `8765` 和 `8766` 两套实现。
- 桌面应用资源与 GitHub 仓库保持一致。

## 验证

- 65 个现有项目的索引不再携带历史正文，体积从约 23.5 MB 显著下降。
- 验证新项目同步、旧项目更新、历史版本按需读取、离线缓存和冲突副本。
- 在电脑网页入口运行回归测试，并通过平板地址健康接口确认服务重启成功。
