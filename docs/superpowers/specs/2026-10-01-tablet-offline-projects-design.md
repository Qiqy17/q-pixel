# Q像素平板离线作品与手动同步设计

日期：2026-10-01（北京时间）
状态：供用户审阅；本文件不是已实现或已发布记录。

## 用户要求与现状

用户要求：平板离线编辑、保存到本地；恢复任意可用网络后，点击“同步电脑”再同步。

源码核查：`web/app.js` 的 `storeProjectsLocally` 使用 localStorage 存正文和索引，异常后仅保留页面内存；保存会继续尝试局域网服务。`web/core/auto-draft.js` 的 IndexedDB 仅有 drafts/history。`web/sw.js` 缓存界面资源，不缓存 /api 项目正文。当前没有 CloudKit 实现。

此前选择 iCloud 的记录用于延续同步路线，CloudKit 配置仍须现场核实。当前局域网服务不能完成任意网络跨电脑同步。

## 方案比较与推荐

1. **推荐：完整 IndexedDB 本地作品库 + 手动同步队列，随后接 iCloud。** 先解决关页重开和大作品保存，独立验证；跨网部分在 CloudKit 与固定 HTTPS 入口配置后联调。依赖较多，但符合最终需求。
2. 继续 localStorage + .qpx 手动备份：成本低，但容量、多作品持久化和操作负担不能满足要求。
3. 仅加强局域网保存：成本较低，跨网同步要求仍未满足。

## 第一阶段：可独立交付的离线作品库

### 持久化与迁移

- 新建独立 IndexedDB 数据库 `q-pixel-projects`，与草稿库分离。stores：projects（完整正文、元数据和本地修订号）、outbox（待同步操作）、syncState（服务端基线）。
- 正文与对应 outbox 在同一 readwrite 事务中提交，必须等事务完成才显示“已保存到本机，待同步”。内存写入不算保存成功。
- 每项目修订号由事务读取后递增；正文指纹用于判定内容相等，设备时间不作为覆盖依据。
- 启动时先读本机索引，打开本机作品优先读持久正文。网络不可用也能新建、打开、编辑、保存、重开已存作品。
- 遗留 localStorage 正文逐项目校验后迁入；迁移事务完成并回读一致后才记录已迁移，保留旧副本至验证结束。索引有条目但无正文的作品标“尚未下载到本机”，不伪装可离线打开。
- 不沿用 120 条截断来删除本机正文或待同步项目；删除由用户操作产生墓碑，恢复也生成新修订。
- 历史与草稿保持原功能；保存成功后仅清理对应修订的草稿。较新的未保存编辑不能被旧保存回调清除。

### 手动同步

- 保存只写本机；恢复网络只更新网络提示，不自动上传待同步作品。用户点击现有“同步电脑文件”启动一轮同步。
- 第一阶段对接现有局域网接口，并明确提示“电脑需在同一局域网”；没有配置跨网服务时，外网连接不显示同步成功。
- outbox 按项目合并待上传最新修订。每次请求捕获修订号，服务端确认该内容已存后只确认此修订；发送途中新编辑保留为待同步。
- 上传前读取服务端正文/指纹，比较共同基线：仅本机变则上传，仅远端变且本机无待写则下载；双方变则持久保存冲突副本，两个版本都保留。未打开的远端作品只更新索引，不默认批量下载全部正文。
- 局域网现有接口没有原子 compare-and-swap：上传后回读核对正文，再清除相应待同步记录；并发风险要在验收中注明。不能把 HTTP 200 或 accepted:true 单独当作内容一致的证明。
- 失败保留队列和本地正文，下一次点击重试；重复同步不产生重复冲突副本。正在编辑的画布不被远端刷新静默替换。

### 离线启动与失败提示

- 先在联网状态打开固定 HTTPS 入口，确认 Service Worker 完成缓存后显示“可离线打开”。首次从未缓存的设备仍需网络。
- 断网重开缓存入口进入完整编辑器；应用更新不清空作品库，不强制刷新存在未保存编辑的页面。
- IndexedDB 不可用、配额不足或事务失败：保留“未保存”，提供 .qpx 备份按钮并说明失败；旧已存作品保持可读。
- 浏览器存储可能被系统清理，不能承诺永久保存；支持主动 .qpx 备份。申请持久存储是尽力请求，不据此宣称绝不丢失。
- 本机存储按 origin 隔离。局域网 IP 更换后的新入口不能直接读取旧入口数据库；第一阶段必须提示原入口/导出迁移限制，最终固定入口解决跨网络入口稳定性。

### 实现边界

新增 `web/core/offline-projects.js` 专管事务与队列；app.js 只连接保存、打开、索引与手动同步入口。同步冲突计算拆为可测试纯函数，复用现有项目模型与指纹。新模块必须加入 index、Service Worker、构建和发布校验清单。

## 第二阶段：iCloud 任意网络同步

这是后续独立交付阶段，第一阶段通过不等于此阶段完成。

- 固定 HTTPS 网页入口承载平板离线应用；不能依赖电脑局域网 IP 作为跨网入口。新入口从旧 origin 通过 .qpx 或联网电脑导入，不声称能跨 origin 自动读取旧 IndexedDB。
- 平板和电脑通过 CloudKit JS 登录同一 Apple 账户，使用用户 private database；网页不能继承系统 iCloud 登录而省略认证。
- 元数据记录与正文 Asset 分离，记录携带正文指纹、父修订和 CloudKit record change tag。采用服务端并发检查，双方修改时保存副本，不使用设备时间直接覆盖。
- 平板上传后显示“已同步到 iCloud”；电脑下一次点击同步并持久保存后才能显示“电脑已接收”。电脑离线时不能提前声称到达电脑。
- 需要用户所有的 CloudKit container ID、网页 API token、Allowed Origins、生产环境 schema，以及固定 HTTPS 地址/部署归属。仅核实配置是否具备，不在聊天或日志索要账户密码、私钥。
- 真实跨网验收：电脑联网、平板使用另一网络，离线保存→重开→恢复网络→手动同步→电脑读取同一内容；再测双端冲突、认证过期和失败重试。

## 第一阶段验收清单

1. 隔离浏览器 48×48 与 500×500 多图层作品：断网保存，关闭/重开应用，像素、图层顺序、色号、编辑设置一致。
2. 保存事务中止、配额异常、数据库不可用：不显示已保存，旧版本可读，备份可导出。
3. 保存与同步乱序回调：旧确认不清除新修订，不回滚当前编辑；两标签同时编辑保留冲突副本。
4. 网络恢复不自动上传；点击同步才上传；失败与刷新后 outbox 仍在，重复点击不重复作品。
5. 旧 localStorage 迁移中断重试不丢正文；超过 120 份作品不会删除未同步项目。
6. 模拟浏览器、已打包、已安装、局域网服务、真实 iPad 离线重开分别记录证据；拿不到真实 iPad 时明确未验收。

## 自审结论

第一阶段可脱离云端配置独立实施，但真实 iPad 验收依赖设备。第二阶段明确列出配置和认证依赖，未配置前不交付“任意网络同步”承诺。两阶段都保留现有作品和未保存编辑。
