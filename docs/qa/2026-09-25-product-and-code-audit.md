## 开发视角：优先处理的问题

1. **P0：局域网服务缺少访问控制。** 已安装版进程以 `--host 0.0.0.0 --http` 运行；服务代码对所有接口发 `Access-Control-Allow-Origin: *`，`/api/projects`、`/api/settings`、项目删除和 AI 生成路径没有鉴权或来源验证。同网段能访问 8766 端口的客户端可能读取、改写、删除工程；若配置 AI 密钥，也可能调用生成接口。桌面模式宜只监听回环地址；平板共享模式需显式启用、配对令牌、限制允许来源与请求体大小。尚未做外网可达性判断。
2. **P0：3D 操作语义不清。** `finish-viewer-entry.js` 禁用 OrbitControls，画布拖动永远进入编辑；`finish-workbench.js` 的“移动视图”按钮只提示用户使用方向按钮。建议将“观察”和“编辑”明确分开，画布附近常驻模式与重置视角入口。
3. **P0：指针取消可能遗留 2D 编辑状态。** 3D 的 `pointercancel` 只调用 `clearPress`，不向共用 2D 编辑器发送结束/取消命令；在已开始拖笔后可能留下 `isPointerDown`。需要在模拟触摸取消、失焦、关闭对话框时验证并修复。
4. **P1：单笔 3D 更新成本高。** `updatePattern` 每次全图分析两遍、重新分组和创建实例网格、连接桥，再重建融合表面；当前 70 ms 延迟只合并短时间事件，不能避免每段笔迹的全图成本。优先做变更区域增量更新或笔迹结束后一次完整重建，并以 120×120、500×500 记录输入到可见的时延。
5. **P1：滑杆重复生成材质和几何。** `setTuning` 对粗糙度、纹理透明度、融边程度统一调用 `setProfile`，后者重建纹理并可能重新生成表面。应区分纯材质参数与几何参数，拖动期间合帧，松手确认几何。
6. **P1：3D 覆盖层的大图成本。** 开启网格或色号时，`drawOverlay` 扫描全部单元格，再按投影判断是否可见；500×500 是 25 万格。先计算视域中的行列范围，并限制标签密度与投影对象分配。
7. **P1：性能监测无法覆盖主线程卡顿。** 低帧率监测只在渲染回调中采样，回调间隔大于 120 ms 时重置窗口，长时间同步建模可能无法触发降档。增加建模耗时和交互响应指标。
8. **P1：标定状态判断过于宽松。** `isCalibrated()` 只判断清单里的 `status` 字段；还未校验实测数据、纹理资源和验收证据。水印解除前需逐项校验，当前状态必须保持“未实物标定”。
9. **P2：文档版本滞后。** `README.zh-CN.md` 仍写 build 9，而实际已安装 build 16，应在发布时从 release-info 自动生成当前版本说明。

## 本轮处理进度

- 源码已改为 3D 默认观察：拖动旋转，滚轮/双指缩放；“编辑图纸”显式切换落笔，画布内有常驻模式按钮和重置视角，右侧绘图工具提前并按模式展开。
- 补上画笔拖动时取消手势、切换模式或关闭面板的编辑结束路径；图纸更新复用一次结构分析，粗糙度单项调整不再重建全部几何。
- 浏览器空白工程实测：观察模式拖动后豆数仍为 0；编辑模式点击后豆数为 1；再切回观察拖动后仍为 1。此项只覆盖浏览器源码版的基本路径。
- 局域网服务访问控制、500×500 性能、MARD 标定及 iPad 实机验收仍列为待处理；本轮没有把它们写为已修复。
