# 作品列表与同步性能验收（2026-09-28）

## 改动

- 服务端维护可重建的轻量工程索引；索引只含列表元数据，缩略图按工程单独读取。
- 单工程保存、删除只更新对应工程文件和索引；旧版批量接口仍可用。
- 前端仅同步新增或较远端更新的工程；普通列表操作不再上传整套工程。回收站完整内容仅在恢复时读取。
- 列表缩略图延后加载和解码；索引无缩略图时仍保留本机已有缩略图。

## 证据

- 修改前，真实服务的 `/api/projects/index` 对 151 个工程耗时 5.93 秒，响应约 3 MB。
- 用同一批 151 个工程的临时副本验证新索引：首次建立 0.466 秒，热读取约 0.001 秒；索引文件 86,215 字节，不包含工程内容或缩略图。
- 临时服务的浏览器实测：热索引请求约 12 毫秒，首页正确显示作品卡片及缩略图。
- 浏览器调用 `setProjectsForTest`：新增工程只向 `/api/projects/<id>` 发一条 POST；未改动的工程列表不发 POST。
- 浏览器从回收站恢复一个仅有远端索引的测试工程后，首页出现该工程，服务端记录保留完整内容且不再标记删除。
- `npm test`：17 个 JavaScript 测试文件、5 个 Python 测试通过；`node --check web/app.js` 和 `git diff --check` 通过。

## 边界

- 浏览器验证使用电脑上的临时服务和工程副本；尚未在真实平板上记录局域网延迟。
- 首次生成索引仍需扫描工程；后续热读取使用索引。单个大工程的首次打开和保存仍需读取或写入该工程完整内容。
