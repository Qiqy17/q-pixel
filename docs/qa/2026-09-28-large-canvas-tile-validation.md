# 大图与分区工程验收（2026-09-28）

## 范围与环境

- 验收对象：先测 Q像素 2.0.0 build 40（提交 `0aedf6d9c7b50dc97a3edba9dca069353939ab53`），随后对验收期间新安装的 build 41（提交 `7b2eb24bfd18135773c5924581afcf3a71169c5f`）复测关键路径。
- 从各安装包内的网页资源和 Python 服务启动独立的本机测试服务，数据目录分别为 `/tmp/qpixel-validation-build40-20260928` 和 `/tmp/qpixel-validation-build41-20260928`。未读写正式工程数据。
- 浏览器：本机 Chrome 无头模式。另以 810 × 1080、触控事件和 2 倍像素密度模拟平板视口。下列耗时是单次本机观测值，不能当作 iPad 性能基准。
- 真 iPad：Mac 的设备列表仍显示配对过的 iPad 8 代为 `unavailable`；用户反馈 iPad 可以检索共享文件，但本轮无法直接验证真机绘制、离线恢复或导出。

build 40 独立服务返回的 500 × 500 分区数据包含 `tileLayout: { rows: 3, cols: 3 }`。导出预览列出 9 个区域，每块为 166–167 格。选择其中一块后，PDF 成功下载、可解析并渲染，文件为单页。

另将原始 500 × 500 工程的连续空白区域填成单色，共 **250,000 个有色格**：填充约 304 ms。保存时本机浏览器缓存空间不足，但电脑服务接受了完整工程（约 1266 ms）；刷新后重新打开约 371 ms，全图 PDF 约 1207 ms 导出成功。这些均为一次本机观测值。断开工程 API 后，修改该工程再保存，页面明确提示“保存未完成：本机空间不足且电脑同步服务不可用，请导出工程文件”，状态显示“未保存”。

**build 41 复测：** 500 × 500 落笔与 3 × 3 分区仍通过；模拟缓存配额不足时，9 个分区图层仍保存到电脑服务。密集单色 250,000 格填充约 302 ms，电脑同步保存约 557 ms，在触控模拟视口重新打开约 343 ms，页面无横向溢出或脚本错误。断开工程 API 后再次编辑，仍显示保存失败且“导出源文件”按钮不可见；PDF 仍可导出，但选择 A4 时物理页尺寸为 4870 × 6888 pt。

## 发现与限制

1. **A4 PDF 物理页尺寸错误。** 在导出预览选择“A4 竖版图纸”并只导出一块 500 × 500 分区时，`pdfinfo` 报告页面为 **4960 × 7016 pt**；build 41 的密集 500 × 500 全图为 **4870 × 6888 pt**，而标准 A4 约为 595 × 842 pt。页面内容完整，但直接按 A4 打印需要额外缩放，实际打印比例不可按标签信任。
2. **密集大图离线保存失败。** 25 万格工程超出本次浏览器 `localStorage` 可用空间；电脑同步在线时可保存，模拟断线时保存失败且状态正确显示“未保存”。页面提示导出工程文件，但其“导出源文件”按钮位于仅标记为 `version` 的面板；当前四个工作阶段只有 `design/color/make/output`，本轮未找到可见入口。需要修正保存回退与入口，不能把提示当作已经可用的恢复路径。
3. **真机验收未完成。** 共享文件可检索是用户反馈，不能替代 iPad 上打开 500 × 500 工程、触控落笔、断网重启恢复及导出的实测。待设备连接可用后逐项补验。
4. **本机耗时只代表单次烟测。** 已覆盖 25 万格单色图纸，但未覆盖连续笔迹、复杂多色图纸、3D 旋转、4K 导出和内存峰值。
