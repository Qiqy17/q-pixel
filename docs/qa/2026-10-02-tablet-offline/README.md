# 平板离线作品库第一阶段验收

日期：2026-10-02（北京时间）。设计依据：`docs/superpowers/specs/2026-10-01-tablet-offline-projects-design.md`。

## 交付内容

- 完整作品与待同步修订在 IndexedDB 同一事务提交；事务失败不清除未保存状态。
- 恢复网络与保存均不上传作品；点击“同步电脑文件”才同步。此阶段仍需同一局域网。
- 上传前核对共同基线，上传后回读核对正文；仅确认发送时的修订，不能清掉发送期间的新修改。
- 双端冲突保留本机修改副本，电脑原稿不覆盖；同浏览器不同连接的过期保存也保留另一份修改。
- 离线另存为、历史恢复、回收站恢复与永久删除均接入持久保存。删除请求也延至手动同步，电脑有未核对修改时保留删除队列。
- 索引显示“可离线打开／尚未下载到本机／待同步”，应用壳缓存就绪后提示此入口可离线打开。
- 保留旧 localStorage 正文；迁移回读校验后从新作品库加载，不沿用 120 条截断删除项目。

## 环境与实际证据

隔离浏览器会话 `qpixel-offline-qa`，静态入口 127.0.0.1:8880；真实现有 Python 服务在 127.0.0.1:8881，以 `/tmp/qpixel-offline-server-qa` 作为独立数据目录。没有写入用户电脑作品库，也没有刷新用户现有页面。

1. **48×48 双图层**：断网保存→刷新→重开，主图层 H2 与第二层 E11 保持，待同步记录仍在。
2. **500×500 双图层**：断网保存，刷新后重开仍为 500×500、两层，边角 H2 保持。
3. **本机故障**：注入数据库事务失败后 save=false、dirty=true，旧格仍为 null；恢复后保存成功。恢复网络与保存的项目 POST 计数均为 0。
4. **实际同步服务**：手动同步产生一个项目 POST，电脑回读指纹一致，待同步数从 1 降到 0。
5. **双端冲突**：电脑增加 H7，本机增加 H4；同步后电脑 H7 不变，本机 H4 在一份冲突副本中，待同步数为 0。重复同步不新增副本。
6. **服务失败**：阻断同步接口，待同步数保持 1；刷新后仍为 1，恢复接口后点击同步清到 0。
7. **实际 UI**：离线点击“另存为→生成新设计”持久创建一份 48×48 合并作品；删除→回收站恢复后 H2 保持；离线历史恢复移除后加的 H3、保留 H2，状态为已保存。
8. **永久删除**：已同步的隔离作品先删除再永久删除，手动同步后电脑 GET 为 404、本机不再显示、待同步数为 0。
9. **遗留迁移**：通过原 project-store 写入旧缓存，再重开；IndexedDB 迁移成功，旧正文仍存在，正文指纹一致，未确认同步的迁入作品加入待同步队列。
10. **新作品身份**：复查发现未命名作品生成正文时 ID 不稳定；已改为首次生成后保持同一个 ID。实际等待 15 秒自动草稿写入后再手动保存，草稿与作品 ID 一致、作品已持久保存、匹配草稿已清理。

## 验收边界与遗留

- 以上是桌面 Chromium 的实际离线和服务交互，不是原生 WKWebView 界面或真实 iPad 的触摸验收。
- `xcrun devicectl list devices` 当前 iPad (8th generation) 为 unavailable，真实设备离线启动未验收。
- iCloud/任意网络同步尚未实施；需要 CloudKit 配置及固定 HTTPS 入口。更换局域网 IP 会更换浏览器存储 origin，不能自动读取旧入口作品；请先从原入口导出 .qpx。
- 浏览器或系统可能清理本机存储，.qpx 仍是主动备份渠道；不能承诺永久保存。
- 现有局域网接口没有原子 compare-and-swap。回读检查与冲突副本降低覆盖风险，但不能把该接口描述为已具备强一致并发写入能力。
- 永久删除后保留不含正文的本机删除标记以防旧索引复活；失败队列不会假报电脑已删除。
- 用户已说明尚无 Apple 开发者账户；当前没有可用的项目 CloudKit 配置，跨网络 iCloud 阶段不能据此标记完成。
